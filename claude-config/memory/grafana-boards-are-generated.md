`docs/grafana/*.json` are **generated output**. Edit
`scripts/build_trading_dashboard.py` and regenerate;
`test_generator_matches_shipped_json` fails if the two drift. I lost a full
pass on 2026-08-01 editing the shipped JSON before that test caught it.

HIG/design rules live in `_hig_pass()` beside `_apple_palette()` — both
recursive post-passes, so a rule is stated once instead of remembered at 179
call sites. Output properties are pinned by `tests/test_dashboard_hig.py`
(15 tests), which asserts *results* rather than implementation. Rationale and
what was deliberately NOT changed is in `docs/grafana/HIG.md`.

Serialization is `indent=2`, `ensure_ascii=False`, **no trailing newline** —
verified to round-trip the four boards byte-identically. Anything else
reflows 475 KB and buries the real diff.

Importing needs a Grafana **service-account** token (`glsa_`) at
`~/.liquiditybot/grafana-sa-token` or `GRAFANA_SA_TOKEN`. The `gc-token` file
beside it is a `glc_` Cloud access-policy token, metrics-write realm only, and
**cannot** write dashboards. Write the file without a BOM: PowerShell 5.1's
`Set-Content -Encoding utf8` adds one and the `glsa_` prefix check then fails
with a misleading "token missing" error. `ConvertFrom-SecureString
-AsPlainText` does not exist on 5.1.

Do not delete that token file to "reset" it — `pc_supervisor` checks
`is_file() and st_size > 0`, so a missing file silently returns auto-import to
the broken state it sat in for 13 days.

### Task 1: L1 — maker-fill hazard time-consistency report (report-only)

**Files:**
- Create: `scripts/fill_hazard_report.py`
- Create: `docs/quant/2026-07-31_fill_hazard_l1.md` (the script writes it)
- Test: `tests/test_fill_hazard_report.py`

**Interfaces:**
- Consumes: `data/replay.py` session reader (recordings in
  `data/recording/session_*.jsonl` + sidecars), `core/fill_calibration.py`
  estimator, the sim fill model's config (`order_manager.sim_fill`:
  `maker_fill_p0` and friends — read them from config.json, do not
  hardcode).
- Produces: a markdown report + exit code 0 (report-only; never gates).

**Requirements (the L1 verdict the TANK program needs):**
1. From every available recording session, reconstruct resting-maker-order
   episodes: for each simulated/dry-run entry order observed in the
   session stream (or, where order events are absent from recordings,
   synthesize episodes by replaying book/trade frames against the resting
   price level — document which mode ran), measure time-to-first-fill
   opportunity: a trade printing at-or-through the resting price.
2. Fit a per-poll discrete hazard h(t) (probability the level is hit in
   poll t given not hit before) and compare: (a) the sim's CONSTANT
   per-poll probability assumption vs (b) the fitted hazard shape
   (Cont-Stoikov-Talreja 2010 / Huang-Lehalle-Rosenbaum 2015 predict
   DECREASING hazard with queue age). Report the fitted curve, its
   Greenwood-style CI, sample sizes, and the KS/likelihood-ratio
   distance between constant and fitted.
3. Verdict block: does the constant-hazard sim misstate cumulative fill
   probability at the order-timeout horizon by more than 10 relative
   percent on these recordings? YES → L2 (label-geometry change +
   200×1200 re-baseline) stays justified; NO → recommend closing L2.
   State the evidence limits honestly (recording count, span, sim-mode
   caveats).
4. No engine change of any kind. Script is runnable standalone
   (`.venv/bin/python scripts/fill_hazard_report.py`) and must not
   require operator input (README "Scripting inputs" rule).
5. Tests: synthetic-episode fixtures (constructed frame sequences with a
   KNOWN hazard) proving the estimator recovers (i) a constant hazard and
   (ii) a decreasing hazard, and that the report file gets written with
   the verdict line present. No network, no dependence on real recordings
   (skip gracefully with a clear message when none exist).

- [ ] Steps: failing tests first (estimator recovery on synthetic
  episodes) → implement estimator + report writer → run the script on the
  real recordings, commit the generated docs/quant report → full battery
  → commit.

### Task 2: K+N — v9 shadow features: event OFI + basis momentum (one bump)

**Files:**
- Modify: `strategies/liquidity_model.py` (view build: event-based
  best-level OFI beside the existing snapshot `imbalance_ratio`)
- Modify: `execution/fair_value.py` OR the view build (basis momentum:
  d(basis_bps)/dt over a short window — put the state where basis_bps
  already lives; keep it out of hot-path recomputation)
- Modify: `ml/features.py` (two new columns + FEATURE_SCHEMA_VERSION 9)
- Modify: `config.json` + `core/config_guard.py` (any new tunables —
  window lengths, EWMA decays — lifted with bounds; defaults chosen from
  the literature, documented in _doc strings, never fitted)
- Test: `tests/test_ofi_feature.py`, `tests/test_basis_momentum.py`,
  existing schema-migration suites must stay green.

**Interfaces:**
- Consumes: consecutive book polls already flowing through the liquidity
  view build (best bid/ask price+size per poll); `basis_bps` as already
  computed in execution/fair_value.py.
- Produces: view keys `ofi_event` (EWMA of signed best-level flow, per
  Cont-Kukanov-Stoikov 2014: e_n = 1{Pb_n>=Pb_{n-1}}·qb_n −
  1{Pb_n<=Pb_{n-1}}·qb_{n-1} − 1{Pa_n<=Pa_{n-1}}·qa_n +
  1{Pa_n>=Pa_{n-1}}·qa_{n-1}, normalized by a rolling depth scale) and
  `basis_mom_bps` (change in basis_bps over the configured window);
  feature columns `ofi_dir` and `basis_mom_dir` (the schema's existing
  *_dir convention: bounded/clipped directional values, NaN-safe 0.0
  when inputs are missing/stale).

**Requirements:**
1. SHADOW: the two view keys/columns feed ONLY the ml feature vector.
   Grep-provable: no read of `ofi_event`/`basis_mom_bps`/`ofi_dir`/
   `basis_mom_dir` in any gate, sizer, exit, or execution module.
2. Wall-time discipline: OFI event deltas normalize by poll interval
   (the THALES A-3 lesson — never per-event units that alias with
   cadence); basis momentum is per-second scaled to bps/min. Both clamp
   and are NaN-safe on missing books/stale feeds.
3. One FEATURE_SCHEMA_VERSION bump 8→9 covering both columns; the
   existing pad-migration keeps v8 rows loadable (verify via the
   existing migration tests + a new explicit v8-row load test).
4. Tests: (i) OFI sign correctness on hand-built poll pairs (bid add =>
   positive, bid cancel/ask add => negative, price-move cases per the
   CKS definition); (ii) cadence invariance (same flow at 2x poll rate
   => same normalized value within tolerance); (iii) basis momentum
   sign + window behavior + staleness => 0.0; (iv) schema v9 length,
   order, and v8 pad-load; (v) shadow-purity source scan (the grep in
   requirement 1 as a test, mirroring tests/test_bracket_divergence.py's
   repo-grep idiom with its _SKIP_DIRS).
5. Promotion criteria from Global Constraints recorded verbatim in the
   features' _doc/comment.

- [ ] Steps: failing tests first → implement view-build OFI + basis
  momentum state → features.py columns + bump → config/guard lifts →
  full battery → single commit → push branch + ff main.
